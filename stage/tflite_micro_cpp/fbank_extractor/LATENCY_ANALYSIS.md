# FBank 特征提取流式延迟分析

## 配置参数

- **Frame shift**: 10ms（原始 FBank 帧间隔）
- **Frame length**: 25ms（每帧长度）
- **LFR parameters**:
  - `lfr_m = 5`（拼接 5 帧）
  - `lfr_n = 3`（每 3 帧输出一个 LFR 帧）
  - `left_padding = (lfr_m - 1) / 2 = 2`（左填充帧数）
- **LFR 输出帧间隔**: 30ms（`lfr_n × frame_shift = 3 × 10ms`）

## LFR 处理流程

### 非流式（批处理）

1. **左填充**：重复第一帧 2 次
   ```
   [pad0, pad1, frame0, frame1, frame2, frame3, ...]
   ```

2. **拼接**：每 3 帧取一次，每次拼接 5 帧
   - LFR 输出 0: [pad0, pad1, frame0, frame1, frame2]
   - LFR 输出 1: [frame1, frame2, frame3, frame4, frame5]
   - LFR 输出 2: [frame4, frame5, frame6, frame7, frame8]
   - ...

### 流式处理延迟分析

为了生成**第一个 LFR 输出帧**（对应原始帧 0），需要：

1. **需要的原始帧**：
   - 原始帧 0（当前帧）
   - 原始帧 1（未来 1 帧）
   - 原始帧 2（未来 2 帧）

2. **拼接过程**：
   ```
   左填充后: [pad0(frame0), pad1(frame0), frame0, frame1, frame2]
   LFR 输出: [frame0, frame0, frame0, frame1, frame2]  (400维)
   ```

3. **延迟计算**：
   - 需要等待未来 **2 个原始帧**
   - 每个原始帧间隔 = 10ms
   - **总延迟 = 2 × 10ms = 20ms**
   - 以 LFR 输出帧为单位：**20ms ÷ 30ms ≈ 0.67 个 LFR 帧**
   
   **重要澄清**：
   - ❌ 延迟 ≠ 2 × 30ms = 60ms（这是错误的）
   - ✅ 延迟 = 2 × 10ms = 20ms（这是正确的）
   - LFR 输出帧间隔（30ms）和延迟（20ms）是不同的概念

## 流式延迟总结

| 阶段 | 延迟（原始帧） | 延迟（LFR帧） | 延迟时间 | 说明 |
|------|--------------|-------------|---------|------|
| **FBank LFR 处理** | 2 帧 | 0.67 帧 | **20ms** | 每个 LFR 输出需要等待未来 2 个原始帧 |
| Encoder chunk 处理 | 0 帧 | 0 帧 | 0ms | 实时处理（chunk_size=10） |
| **总延迟** | 2 帧 | 0.67 帧 | **20ms** | 固定延迟，不累积 |

**注意**：
- 原始 FBank 帧间隔：10ms
- LFR 输出帧间隔：30ms（`lfr_n × 10ms = 3 × 10ms`）

### 流式处理时间线

```
时间点 | 收到原始帧 | 可输出的 LFR | 延迟（ms）| 延迟（LFR帧）
-------|-----------|--------------|----------|-------------
0ms    | frame0    | -            | -        | -
10ms   | frame1    | -            | -        | -
20ms   | frame2    | LFR输出0     | 20ms     | 0.67 帧
30ms   | frame3    | -            | -        | -
40ms   | frame4    | -            | -        | -
50ms   | frame5    | LFR输出1     | 20ms     | 0.67 帧
60ms   | frame6    | -            | -        | -
70ms   | frame7    | -            | -        | -
80ms   | frame8    | LFR输出2     | 20ms     | 0.67 帧
```

**关键点**：
- 每个 LFR 输出帧需要等待未来 **2 个原始帧**（20ms）
- 延迟是**固定的 20ms**，不会累积
- 由于 `lfr_n=3`，每 3 个原始帧（30ms）输出 1 个 LFR 帧
- **LFR 输出帧间隔：30ms**（这是输出频率）
- **延迟：20ms**（这是等待时间）
- **重要**：延迟（20ms）≠ LFR 输出帧间隔（30ms）
  - 延迟 = 2 个原始帧 = 2 × 10ms = 20ms
  - LFR 输出帧间隔 = 3 个原始帧 = 3 × 10ms = 30ms
  - 延迟以 LFR 帧为单位 = 20ms ÷ 30ms = 0.67 个 LFR 输出帧

## 详细说明

### 为什么需要 2 帧延迟？

1. **LFR 拼接窗口**：每个 LFR 输出帧需要拼接 5 帧
2. **左填充**：前 2 帧是重复的第一帧（历史信息，无延迟）
3. **未来帧需求**：需要原始帧 0、1、2 才能完整拼接
4. **输出频率**：每 3 帧输出一个 LFR 帧（降采样）

### 流式实现建议

如果要实现真正的流式处理（最小延迟），可以考虑：

1. **方案 1：接受 20ms 延迟**（推荐）
   - 简单实现
   - 延迟可接受（20ms 对语音识别来说很小）
   - 与批处理结果一致

2. **方案 2：减少 LFR 窗口**（不推荐）
   - 修改 `lfr_m` 和 `lfr_n`
   - 需要重新训练模型
   - 可能影响识别精度

3. **方案 3：流式 LFR 缓冲**（复杂）
   - 维护一个滑动窗口缓冲区
   - 每收到新帧就尝试输出
   - 需要仔细处理边界情况

## 实际影响

- **20ms 延迟**：对于实时语音识别来说非常小
- **用户体验**：几乎感觉不到延迟
- **对比**：
  - 人类反应时间：~200ms
  - 网络延迟：通常 50-200ms
  - 20ms 延迟：可忽略不计

## 结论

**FBank 特征提取的流式延迟为 20ms**，相当于：
- **2 个原始 FBank 帧**（每帧 10ms）
- **0.67 个 LFR 输出帧**（每帧 30ms）

这对于实时语音识别应用来说是可以接受的。延迟是固定的，不会累积。
